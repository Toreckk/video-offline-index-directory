# v0.3.0 Native Media-Probe Evaluation

Measured on 2026-08-27 on the Windows x86-64 development host. This note records the release decision; it is not a general performance claim for every library or computer.

## Candidate and provenance

The evaluation used BtbN's `ffmpeg-master-latest-win64-lgpl-shared.zip`, one of the Windows build sources linked by the official [FFmpeg download page](https://ffmpeg.org/download.html). The archive's SHA-256 matched its published checksum:

`7eb0dbbacd1ed7e3323395d019dba6d269055d757832d2ede669efa64f8192d0`

FFmpeg is LGPL by default but can become GPL when GPL components are enabled. Its own [legal guidance](https://ffmpeg.org/legal.html) also describes notices, source availability, and dynamic-linking expectations. VOID therefore evaluated an explicitly LGPL shared build and did not use the available GPL Windows package as a bundling candidate.

## Corpus and method

- 12 disposable videos: 6 MP4 and 6 WebM.
- Fixtures were generated locally with the same downloaded build and contained short synthetic video/audio streams.
- The ignored Rust corpus test invoked `ffprobe` once per file through the same parser used by the desktop adapter.
- Every invocation requested structured JSON and extracted duration, dimensions, video codec, and audio codec.
- The existing WebView two-pass thumbnail implementation was left unchanged; this prototype measures metadata probing, not image generation.

## Results

| Pass | Success | Total | Average per file |
| --- | ---: | ---: | ---: |
| Initial recorded pass | 12/12 | 514.24 ms | 42.85 ms |
| Rebuilt-test pass | 12/12 | 422.37 ms | 35.20 ms |
| Immediate warm repeat | 12/12 | 422.31 ms | 35.19 ms |

The warm repeat was effectively unchanged. Process startup dominates this small synthetic corpus, so the result supports bounded background enrichment but does not justify claiming faster thumbnail generation.

Packaging the evaluated build would add approximately 67,716,598 bytes (64.58 MiB) as a compressed download and 153,134,080 bytes (146.04 MiB) for its runtime `bin` directory before installer compression. Shipping it would also add third-party notices and corresponding-source distribution obligations.

## v0.3.0 decision

**Do not bundle FFmpeg or ffprobe in v0.3.0.**

The shared media-probe port and desktop adapter remain available as an optional capability. VOID detects a system `ffprobe`, or a developer/test override supplied through `VOID_FFPROBE_PATH`. When unavailable, scanning, cached metadata, WebView thumbnails, playback, duration filtering, and Library Health continue without a blocking error.

This preserves a small installer and avoids taking on a binary update and license-compliance surface before the metadata benefit is proven on real user libraries. Technical metadata is cached when the adapter is available, and enrichment is queued after normal thumbnail scheduling so it does not delay the quick visual pass.

## Reconsideration gate

A future release may bundle or manage a probe only after it has:

- a pinned, reproducible LGPL-compatible build and documented source/notices publication;
- real-library MP4/WebM coverage, including corrupt and unusual stream layouts;
- an installer-size budget accepted as a product tradeoff;
- cancellation, timeout, and upgrade ownership defined;
- evidence that the native path materially improves user-visible metadata or thumbnail reliability.
