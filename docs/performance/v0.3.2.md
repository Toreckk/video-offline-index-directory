# v0.3.2 thumbnail reuse and collection rendering

## Problem

The persistent IndexedDB/desktop disk cache already avoided regenerating thumbnails, but each mounted `MediaTile` still read the JPEG and created its own object URL. Navigating from Explorer to a smart collection could therefore reread and decode the same resources. Collections also rendered every matching tile at once, unlike the virtualized Explorer grid, which made multi-thousand-video collections prone to long stalls.

## Implementation

- A shared resource layer is keyed by the existing versioned thumbnail blob key.
- Concurrent consumers share one persistent read and object URL through explicit leases.
- Unmounted resources remain available for navigation reuse, with at most 256 unused URLs retained. Least-recently-used entries are revoked on eviction; active leases are never revoked.
- Replacing a cached blob invalidates future leases while allowing current consumers to finish safely. Clearing the persistent cache also clears the shared resource layer.
- Explorer and opened smart collections use one responsive TanStack Virtual grid. The full queue remains available to playback while the DOM contains only visible and overscanned tiles.

The disk/IndexedDB cache remains the source of truth. This session layer neither changes thumbnail generation nor duplicates persisted media data.

## Repeatable benchmark

Run:

```text
pnpm bench:v0.3.2
```

Fixture: jsdom, 1,184 × 900 viewport, comfortable 240 px tiles, one cold iteration per structural case. These timings are regression smoke measurements rather than statistically stable browser-performance claims.

| Scenario | Measured time | Structural assertion |
| --- | ---: | --- |
| 2,500-video collection grid | 123.89 ms | Fewer than 100 mounted tiles |
| 5,000-video collection grid | 94.99 ms | Fewer than 100 mounted tiles |
| Explorer → Collection reuse for 100 thumbnails | 2.88 ms | Exactly 100 persistent reads across both views |

The 5,000-video timing being lower than the 2,500-video timing is ordinary single-sample noise; the release gate is bounded mounting and deduplicated reads. Automated tests independently enforce both invariants.
