## Quick test on your existing 2,500+ video library

1. Stop the old development process and start `pnpm dev:desktop` again after pulling the candidate. If a migration preview appears, export it and choose **Migrate and continue**. It should appear once per new data namespace, not on every restart.
2. On **Library**, click **Reconnect Library**. If a picker opens, select your usual **same full path**. Expect Connected and a scan. Cancel once to verify the saved library stays intact; selecting another same-named folder must show a useful error. No browser-permission wording should appear for native access.
3. Let discovery finish. Compare video count with your earlier baseline. Scroll rapidly, search filenames, use tags/favorites/duration, switch Explorer/Collections/Library and return. Thumbnails should settle without repeated flickering or a permanent blank `ready` tile. Broad speed/memory budgets are v0.5, but regressions or unresponsive controls are defects now.
4. Favorite two clips, add a tag and implication, create a smart collection, watch part of a video, change volume and a durable setting. Restart and verify exact contents, library ID continuity, thumbnail recovery and resume. Repeat after a manual rescan. Playback order/repeat remain intentionally session settings.
5. Play MP4 and WebM, rapidly use next/previous, close with Escape, reopen, switch files and close the window during playback. Exactly the selected video should be audible; no sound should continue after closing. Check progress after restarting. A damaged/unsupported clip should show a useful error and the next healthy clip should play.
   Also close the desktop window while idle: it should disappear promptly. Close just after changing a tag or playback position: a brief **Saving before closing** notice may appear. In a disposable profile with an intentionally blocked save, verify **Retry save**, **Export recovery data**, **Keep app open**, and **Close without saving** are understandable and that an unsaved edit is never silently discarded. Do not damage your normal library to simulate a failure.
6. Use only keyboard to open/close folder setup, player and video information. Tab/Shift+Tab stay in the active dialog, Escape closes it, and focus returns to its trigger. In **Manage video tags**, click and type in both **Search tags** and **Quick create or add existing**, then create/assign a tag. Repeat in fullscreen; Escape closes the popup first and returns focus to its trigger, then a second Escape handles the player/fullscreen. Check at 100%, 150% and 200% display scaling.

If reconnect fails, copy its visible error. Do **not** clear app data. See [data recovery](DATA_RECOVERY.md).

## Disposable correctness checks

Work on copies in a test folder. `fixtures/media` contains a tiny synthetic MP4/WebM corpus with tones; it contains no personal media.

| Test | Action | Expected result |
| --- | --- | --- |
| Rename | Tag/favorite/play a copy, then rename it while VOID is open and again while closed | Unique unchanged file identity retains tags/progress. Ambiguous hard links or occupied destinations do not silently inherit another file's records. |
| Replacement | Replace a clip at the same path with a different size/mtime/file identity | Old thumbnail, dimensions and codecs are invalidated; new media is enriched. |
| Unavailable files | Disconnect a disposable drive or deny a test subtree; rescan, then restore access | Prior records survive. Unseen files show unavailable; reconnect/rescan restores them. Missing data must not be treated as a proven deletion. |
| Cache | Clear thumbnail cache, navigate away/back, restart; test a corrupt JPEG in a disposable cache profile | Visible images regenerate. Repeated decode failure stops retrying and shows an error; user organization and videos survive. |
| Backup ownership | Create libraries A/B with equal relative paths and different tags/progress. Export active and all scopes; preview in B | Preview/cancel changes nothing. A one-library import explicitly maps to B; all-library data retains A/B ownership. Unmatched records remain recoverable. |
| Restore | Export recovery data, edit organization, preview a retained pre-import snapshot and restore | Listed stores are replaced only after confirmation, unlisted stores stay, app reloads, prior state remains recoverable. |
| Bad imports | Try malformed JSON, an unsupported schema, oversized or deeply nested data | Clear rejection, no partial changes or success message. |
| Cleanup | Make exact disposable copies, choose keeper and confirm; repeat with a changed or locked candidate | Keeper remains, changed/locked files are skipped/failed. Restore the recycled file and follow `.void/cleanup-*/recovery.json` back to its original empty path. |
| Missing helper | Launch without ffprobe, then with `VOID_FFPROBE_PATH` configured | Playback/thumbnail indexing works without it; optional duration/codec probing works when present. |

Use a **separate Windows account or disposable test profile** for corrupt/read-only database, revision-conflict and migration interruption tests. Export first. Existing automated fixtures cover those failure contracts, but real filesystem/installer behavior still needs runtime evidence. Never corrupt your normal metadata store to test recovery.

## Installers: required before release

For **each** NSIS `.exe` and MSI `.msi`, use a clean/disposable Windows account or VM:

1. Record filename/SHA-256 and exact candidate commit. Confirm the MIT notice is available in the installer or installed bundle. Install clean, launch, scan the synthetic folder, play both files and restart after editing organization.
2. Separately install published v0.3.2 of the **same format**, create representative library/tags/relations/favorites/collections/playback/settings, close it, then install v0.4 over it. Verify a single registered VOID installation and one migration, exact before/after data and same source files.
3. Close/reopen several times. Confirm no duplicate app registration or title bar, no repeat migration prompt, no stuck reconnect button and no leftover audio/probe process after settling.
4. Uninstall. Verify source videos are untouched and record the app-data retention behavior. Reinstall and check the documented recovery path. Switching NSIS/MSI is not a same-format upgrade test.

Signed installers and automatic updates are later milestones. The v0.4 artifacts are unsigned. Manual installer gates are **pending until a tester records results**; a successful package build is insufficient.

Optional local native corpus/Recycle Bin tests:

```powershell
$env:VOID_FFPROBE_PATH = 'C:\path\to\ffprobe.exe'
$env:VOID_MEDIA_PROBE_FIXTURE = (Resolve-Path fixtures/media).Path
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --lib benchmarks_a_configured_media_corpus -- --ignored --nocapture
New-Item -ItemType Directory -Force artifacts | Out-Null
$env:VOID_RECYCLE_FIXTURE_ROOT = (Resolve-Path artifacts).Path
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml --lib disposable_file_round_trip -- --ignored --nocapture
```

The Recycle Bin test creates its own random disposable folder, matches only that generated path in the bin and restores it. Run it in an ordinary Windows user session: the filesystem sandbox's bin behavior did not reproduce the normal session. Do not substitute a personal video path. Source/fixture hashes are recorded in [the corpus manifest](../fixtures/media/README.md).
