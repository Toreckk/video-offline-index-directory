## Highlights

- Desktop tags, favorites, collections, playback records, settings and library references now save through transactional SQLite storage. The browser has a matching transactional storage adapter. Save failures are visible and recovery exports preserve data that could not be saved.
- First use previews legacy data before migration and retains a recovery snapshot. Metadata imports identify their scope, validate limits and schema, and complete durably before reporting success.
- Reconnect can reauthorize a migrated desktop library through the native folder picker while retaining its identity. Incomplete scans preserve unavailable records; uniquely verified renames move organization and catalog records together.
- Player sessions release outgoing media, ignore stale callbacks and report playback failures. Desktop close captures pending progress, closes immediately when no save remains, and explains slow/failed saves with recovery choices. Tag-popup inputs work inside the player, including fullscreen. Critical dialogs contain keyboard focus and restore it when closed.
- Missing/corrupt thumbnails receive bounded regeneration. Optional ffprobe jobs have separate scheduling, cancellation, deadlines, output limits and local-file/container restrictions.
- Exact duplicate cleanup protects verified file handles, saves keeper metadata first and records recovery information for staged Recycle Bin operations. Cleanup still requires explicit confirmation.
- The assessment, roadmap through v1.0, performance plan, recovery guide and release process are consolidated. Packaging is separate from explicitly dispatched publication, with checksums, dependency notices, build provenance and automatic verification of public downloads.

## Migration and recovery

Export a metadata backup from v0.3.2 before upgrading. Use the same installer format.
On first launch, inspect the migration preview and choose **Migrate and continue**.
Only legacy data visible to that application's current web origin can be migrated.
Development uses a separate native data namespace from the installed application;
use explicit exports/imports to transfer organization between them.

If Library says reconnect is needed, click **Reconnect Library** and select the
same full folder path if prompted. Canceling leaves the saved reference intact.
Do not clear app data to repair this state. See [data recovery](https://github.com/Toreckk/video-offline-index-directory/blob/v0.4.0/docs/DATA_RECOVERY.md)
for retained snapshots, failed saves, downgrade limitations and restore steps.

Recycle Bin restore returns a cleaned-up file to VOID's staging directory. Use
the corresponding `.void/cleanup-*/recovery.json` to move it back to its original
empty path; do not overwrite an existing replacement.

## Compatibility and known limits

Windows 10/11 x86-64 remains the desktop target. Automatic updates and additional
formats are outside this release. MP4/WebM playback depends
on installed WebView2 codecs; ffprobe is optional and is not bundled. Development
and CI use Node 24.11.1, pnpm 11.19.0 and Rust 1.98.0.

VOID's source is [MIT-licensed](https://github.com/Toreckk/video-offline-index-directory/blob/v0.4.0/LICENSE). Third-party dependencies retain
their own terms; [dependency review](https://github.com/Toreckk/video-offline-index-directory/blob/v0.4.0/docs/DEPENDENCY_REVIEW.md) records the advisory
results, remaining upstream warnings and license considerations.

Whole-catalog writes, full-root watcher scans, thumbnail-cache I/O and representative
desktop memory/latency measurements remain explicit v0.5 work packages. v0.6 covers
the broader UI/logo redesign. This release does not claim those performance or
design milestones are complete.
